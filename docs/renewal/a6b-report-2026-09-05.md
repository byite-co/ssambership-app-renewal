## 2. `bodyBehindAppBar` 단일 해법 — `AppPageBody`

A-4a 보고서 §7이 경고한 "앱바 뒤 본문 vs `ensureVisible` 테스트" 충돌은 규칙 하나로 정리했다(`lib/design/widgets/app_page.dart`).

- `Scaffold(extendBodyBehindAppBar: true)` 로 본문을 화면 맨 위까지 늘린다.
- 본문 **바깥에** 앱바 높이(상태바 포함 = `MediaQuery.padding.top`)만큼 `Padding` 을 두어 **스크롤 뷰포트는 항상 앱바 아래에서 시작**한다 → 항목을 뷰포트 맨 위로 맞추는 `ensureVisible` 기반 테스트에서 앱바가 탭을 가리지 않는다(`iq_detail`·`iq_create`·`mypage`·`mentor_detail`·`pdf_page_select`·`mentor_plans` 테스트 무수정 통과).
- `ClipRect` 로 화면 상단에서 자르고, 스크롤 뷰가 `clipBehavior: Clip.none` 이면 뷰포트 위로 넘어간 항목이 그대로 그려져 **유리 앱바 뒤로 비친다**.
- 자식 `MediaQuery` 의 상단 패딩을 제거해 넘겨 이중 여백 0 (A-4a 의 112px 이중 인셋 해소, `IqCreate` 의 `bodyBehindAppBar:false` 분기·`settlement_lines` 의 topInset 패딩 삭제).
- 하단 고정 바(`AppPage.bottom`·`ChatInputBar`·댓글 바)는 `GlassSurface.bar` 이고 본문 패딩은 `AppPage.contentPadding(context)` 가 `MediaQuery.padding.bottom`(탭바/하단 바 높이)을 더한다.

모든 화면이 같은 규칙을 쓴다(`AppPage` 33개 화면 + `HomeShellChrome`). 예외는 `Scaffold` 를 직접 쓰는 셸·미디어 뷰어·전체화면 진입뿐이며 디자인 잠금 테스트가 명시 목록으로 잠근다.

## 4. 화면별 처리와 판단

- **§3-1 질문방 목록**: 행마다 요금제 라벨 + `SubscriptionCopy.quotaSentence`('이번 주 9개 중 9개 남았어요' / '질문 무제한' / '이번 주 질문을 다 썼어요') · 멘토 최근 노트 1줄(방마다 `notes()` best-effort) · '답변 N' 역할색 배지 · 해지 예정 배지('해지 예정 · 9월 5일까지').
- **§3-2 대화**: 말풍선 둘 다 불투명(역할색 + 흰 글자 / 유리 실효색 `#F6F9FC` + 링) · 폭 80% · 사진은 말풍선 안 인라인 + '사진 · 탭하면 전체화면' 캡션. 목업의 하단 '답변을 확인했어요' 확인 바는 **넣지 않았다** — 확인 동작은 질문 목록 카드('답변 확인 완료')에 있고 이번 작업은 스타일 전용이라 동작 위치를 옮기지 않았다.
- **§3-3 새 질문**: 라벨 문장형('어떤 과목인가요?' · '무엇이 궁금한가요?') · 과목 드롭다운 → `ChipScroll`(테스트 무수정 통과) · 입력 채움 `AppColors.inputFill = #E9EBEF`(전 입력 공통) · 하단 '질문 보내기'. 사진은 생성 RPC 가 첨부를 받지 않아 질문 생성 뒤 대화 입력 바에서 붙인다 — **첨부 직후 1회 펜 안내**는 그 입력 바(`ChatInputBar` 대기 미리보기)에 넣었고 썸네일 탭도 주석 화면으로 간다. 1회 기억은 `shared_preferences`(기존 의존성) 키 `question_room_pen_hint_shown_v1`, 저장 실패 시 실행 단위 기억.
- **§3-4 소진**: 질문 목록 하단 바가 '멘토 · 요금제' / '이번 주 질문을 다 썼어요' / '8월 27일 목요일에 다시 채워져요'(RPC `week_end` 있을 때만) / 주요 버튼 '개별질문으로 지금 물어보기'(기존 `/iq/new?mentor=` 화면) / 웹 안내 한 줄. 목업의 '평균 2,500원 · 보통 3시간 안에 답변' 은 앱에 데이터 원천이 없어 **생략**(날조 금지), '상위 요금제로 바꾸기' 는 커머스 제로로 **넣지 않았다**.
- **§4-1 인박스**: '오늘 답변할 질문 N개가 있어요' · 답변 대기 우선 → 최근 활동순 고정 정렬(정렬 옵션 없음, §7) · 내 최근 노트 1줄 · '답변 대기 N' 배지 · '노트 없음'. 목업의 '프리미엄 · 이번 주 3개 사용' 은 멘토가 학생별 사용량을 읽을 RPC 가 없어(신규 RPC 금지) 생략.
- **§2-1 답변**: A-4a 배너 구조 그대로 — 역할 틴트 블록 + 📌 로 목록의 노트 한 줄(`NotePreviewLine`)과 같은 언어. 앱바 부제(학생명) 는 `AppPage.subtitle`.
- **§5-4/5-5 개별질문**: 1,626줄 상세는 토큰 치환 + `AppPage` + 하단 유리 바 + `AppInputField` 컴포저. 작성자 구분 말풍선(학생/멘토/미확인)은 `ConversationBubble` 그대로.
- **§5-2/5-3 멘토**: 카드·상세 유리화, 과목 중립 배지, 활동 통계. **'구독하기'는 A-4b 전까지 웹 브릿지 안내(`CommerceNoticeCard`) 유지** — §9.
- **§5-6 커뮤니티 — 숏폼 오버레이**: 카드는 4:5 남색 미디어 위 아래쪽 그라디언트 스크림에 멘토 배지·작성자·제목·좋아요·조회수를 흰 글자로 얹었다(히트테스트 제외 → 카드 탭 = 상세, 재생 어포던스·시맨틱 그대로). 상세도 플레이어/썸네일 위에 같은 오버레이, 설명·반응·댓글은 아래 유리 영역. 플레이스홀더는 남색. 목업의 전체 화면 세로 피드(추천/팔로잉 탭)는 구조 변경이라 만들지 않았다.
- **§5-7 알림**: 안 읽음 = 왼쪽 점 하나(역할색), 유형은 중립 배지. 테스트가 기대하는 '읽음' 버튼·'안 읽음' 카운트 배지는 유지.
- **§3-5 마이페이지**: '다음 갱신 7/27' → '7월 27일에 갱신돼요'(해지 예정이면 '…에 해지돼요'), 조회만 배지, 유리 섹션, 설정 토글 shrinkWrap(설정 섹션 800×600 테스트 표면 유지). '보유 캐시' 라벨은 `wallet_stale_test` 가 17곳에서 단언해 **유지**했다(§5).
