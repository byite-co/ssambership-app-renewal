## 1. 판정 기준

| 판정 | 뜻 |
|---|---|
| **A-4a 앱 단독** | `authenticated` 가 (a) RLS 정책 + 테이블 권한으로 직접 쓰기가 되거나 (b) `authenticated` EXECUTE 가 있는 RPC 가 있다. 앱 저장소 변경만으로 동작한다 |
| **DB-4 서버 선행** | 쓰기 경로가 `service_role` 전용이다(테이블 권한 회수·정책 부재·RPC 부재). 웹 저장소 pack 에 `api_app_v1` 래퍼가 먼저 필요하다 |
| **보류** | 객체는 있으나 진입 맥락이 앱 범위 밖이거나, 오너의 범위 결정이 걸려 있다 |

판정에서 반복해서 걸린 사실 두 가지:

1. **테이블 단위 REVOKE 는 RLS 정책보다 우선한다.** `mentor_profiles`(`20260731135324`)·
   `mentor_plans`(`20260731135445`)·`users` UPDATE(`20260803170552` A절)·`community_posts`
   (`20260731170632`)는 `REVOKE ALL … FROM anon, authenticated; GRANT SELECT` 가 적용돼 있어,
   `mentor_update_own` 같은 정책이 남아 있어도 직접 쓰기가 권한 단계에서 거부된다.
2. **2026-08-02 default ACL 하드닝**(`20260802000000`) 이후 만든 테이블은 명시 GRANT 가 없으면
   `authenticated` 가 접근할 수 없다. 이번 후보의 직접 쓰기 테이블은 전부 그 이전 생성분
   (077 `mentor_school_verifications`·089 `mentor_academic_record_change_requests`·
   152 `notification_settings`)이고, 152 는 명시 GRANT 까지 있다. 팩 안에 이 세 테이블의 권한을
   회수한 후속 마이그레이션은 없다(grep 0건).

## 5. 2단계 착수 전 오너 확인 항목

### 5-1. `api_web_v1` 쓰기 RPC 를 앱이 직접 부르는 문제 (#1 #2 α1 α2 α7)

현재 앱은 `api_web_v1` 을 **뷰 읽기**(`my_wallet_v1`·`my_cash_ledger_v1`·`mentor_directory_v1`·`community_posts_v1`·`community_comments_v1`)에만 쓰고,
쓰기 RPC 는 `api_app_v1`(`user_profile_update_self`·`community_post_*`·`ensure_free_question_room`)과 `public`(`qna_*`·`iq_*`)만 쓴다.
F13·F8·F7·마케팅 동의는 `api_web_v1` 에만 있고 `authenticated` EXECUTE 가 있어 **권한상 앱 단독**이지만, 리뷰 §7.4·B1 은 "쓰기는 `api_app_v1`" 원칙으로 twin 선행을 권고한다.

선택지: (a) 2단계에서 `api_web_v1` 쓰기 RPC 를 직접 호출하고 앱 계약 문서에 "self 쓰기 RPC 의 `api_web_v1` 교차 사용"을 명문화 · (b) DB-4 에서 twin 을 만든 뒤 #1 #2 를 A-4b 로 미룸.
**권고 (a)** — 멘토 74명 중 계좌 등록 4명이라는 현재 상황이 우선이고, twin 이 나중에 생기면 스키마 문자열 한 곳만 바꾸면 된다.

### 5-2. `iq_create_boundary_test.dart` 계약 갱신 (#11)

이 계약 테스트는 "신규 개별질문 등록은 웹 전용(2026-08-05)"을 정적 검색으로 잠근다. 앱에서 등록을 열면
`lib/ 에서 iq_create_screen import 는 자기 자신뿐` · `IqCreateScreen 생성자 호출 0` · `route table 에 IqCreate 없음` 3건이 반드시 실패한다.
원칙 4("기존 1,578 테스트 무수정 통과")를 문자 그대로 지키면 #11 은 열 수 없다. **의도된 계약 변경으로 이 파일을 갱신(경계 반전)하는 것을 승인해 달라.** 웹 브릿지 URL 테스트 4건은 유지 가능하다.

### 5-3. 개별질문 "과목" (#11)

`create_individual_question_as_student` 에 과목 인자가 없다(코어에 null 고정). 2단계 화면은 과목 없이 만들거나, 과목을 제목 앞에 붙이는 표시 규칙만 둔다. 저장이 필요하면 C4 서버 선행.

### 5-4. 환불 예상액만 먼저 보여줄지 (#9)

INSERT 는 DB-4 지만 예상액(별표4)과 pending 상태는 지금 읽을 수 있다. 2단계에 "환불 예상액 + 신청은 웹" 읽기 화면을 넣을지, DB-4 뒤 한 번에 할지 결정.
넣는다면 충전 유도로 읽히지 않게 금액·사유만 표시한다.

### 5-5. α 항목 2단계 포함 범위

α1·α2(구독 열림·프로필 편집)·α4·α5(리뷰 답글·작성)·α6(오답 표시)·α7(마케팅 동의)은 앱 단독이다. 지시서 순서(멘토 정산 계좌 → … → 공통 알림 설정) 뒤에 붙일지, A-4b 로 넘길지 결정.
α3 아바타는 2026-07 "웹 전용" 결정 번복이 필요하다.
