## 6. DB-4 입력 추가분(이번 구현에서 확인된 것)

- **개별질문 과목**: `create_individual_question_as_student` 는 과목 인자를 받지 않고, `individual_questions.subject` 본인 UPDATE 정책이 없다(`iq_select_party` SELECT 만). 앱 등록 화면은 RPC 가 받는 대로(과목 없음). 과목을 받으려면 RPC 인자 추가.
- **연결노트 `UNIQUE(mentor_student_room_id, author_id)` 해제**(`20260806033452`): 앱은 INSERT 전용이라 두 번째 노트가 23505 → "이미 남긴 노트가 있어요. 곧 여러 개를 남길 수 있게 돼요" 표시. 제약이 풀리면 이 문구는 더 나오지 않는다(앱 변경 불필요).
- **`api_app_v1` twin**(F7/F8/F13) — 리뷰 B1. 앱은 지금 `api_web_v1` 을 부른다.
- 활동 일시중지/종료(#6), 요금제 활성 토글(#2 일부), 구독 해지(#8), 환불(#9), 재학 상태(#12), 분쟁(#10) — 1단계 판정 그대로 서버 선행.
- **학력 인증 검토 중 잠금**: 웹과 같이 `pending` 이면 재제출을 잠근다. 멘토 승인 시 서버가 만드는 "서류 없는 pending 행"도 잠기므로, 신규 승인 멘토가 서류를 올리려면 관리자 확정이 먼저 필요하다 — 앱은 그 행을 "서류 없음 · 관리자 확정 대기"로 구분해 보여준다. 정책 확인 필요(서류 없는 pending 은 제출 허용?).
- 오답 표시는 스레드 단위(`qna_flag_wrong_answer(p_thread_id)`) — 메시지 단위 표시가 필요하면 RPC 추가.

## 7. A-6b(기존 화면 재스타일)에서 문제될 것

1. **`V3Page` 는 임시 껍데기다.** 앱 트리가 아직 v3 테마에 연결돼 있지 않아 새 화면마다 `Theme(v3.AppTheme.build())`·`RoleTheme`·`AppBackground`·`GlassAppBar` 를 스스로 두른다(`lib/shared/widgets/v3_page.dart`). A-6b 에서 루트 테마를 v3 로 바꾸면 이 래핑은 중복이 되므로 `V3Page` 를 얇게 줄이거나 제거해야 한다. `showV3BottomSheet` 도 같은 이유로 시트 서브트리에 테마를 다시 두른다.
2. **글래스 앱바 뒤로 본문을 늘리면(`extendBodyBehindAppBar`) `ensureVisible` 기반 기존 위젯 테스트가 깨진다.** 항목을 뷰포트 맨 위에 맞추면 앱바가 탭을 가린다. 개별질문 등록은 `V3Page.bodyBehindAppBar: false` 로 뒀다. A-6b 에서 채팅·첨부 화면을 글래스 앱바로 바꿀 때 같은 문제가 난다(첨부·PDF·첨삭 테스트).
3. **`AppBadge` 가 두 개다**: `design/widgets/app_badge.dart`(옛, `tinted` 인자)와 `design/widgets/glass_badge.dart`(A-6a). 같은 클래스명이라 한 파일에서 둘 다 import 할 수 없다. A-6b 에서 옛 것을 없애거나 이름을 바꿔야 한다.
4. **정산 탭 본문은 옛 `MentorSettlementsTabBody`('답변 · 정산 요약') 그대로**이고 새 정산 허브는 AppBar 아이콘으로만 연다(골든·`home_shell_test` 고정 때문). A-6b 에서 탭 본문을 정산 허브(`MentorSettlementScreen`)로 바꾸는 것이 자연스럽다. 마이페이지의 멘토 정산 진입도 같은 방식(아이콘)이다.
5. **`kPayoutManageNoticeText`("정산·출금은 웹 계정에서 관리돼요", `core/commerce/commerce_policy.dart`)** 를 `MentorDashboardSection` 이 정산 탭 본문과 마이페이지 양쪽에 `CommerceNoticeCard` 로 띄운다. 정산 계좌·요금제가 앱에 들어온 뒤로 사실과 어긋나지만 두 골든(`mentor_settlements_tab`·`mypage_mentor`)을 지키려 손대지 않았다 — A-6b 에서 문구를 바꾸고 정산 허브 진입으로 대체해야 한다(캐시 충전 안내 `kRechargeNoticeText` 는 정책상 그대로).
6. 채팅·답변 화면(`ChatScreen`·`MentorAnswerScreen`)은 옛 `ColorTokens` 기반이고, 이번에 넣은 오답 배너·노트 배너·노트 시트만 A-6a 토큰이다. 재스타일 때 두 토큰이 한 화면에 섞여 있으니 함께 바꿔야 한다.
7. 새 화면의 위젯 테스트는 세로가 긴 표면(1,600~3,600px)을 쓴다(글래스 카드 여백 때문에 800×600 에 다 들어가지 않는다). 재스타일로 높이가 바뀌어도 테스트는 영향이 없지만, 기존 800×600 테스트가 있는 화면을 카드형으로 바꿀 때는 개별질문 등록에서 겪은 대로 레이아웃 예산을 먼저 잡아야 한다.
8. `HomeShell`·`MyPageRoutePage` 의 정산 허브 아이콘(`MentorSettlementScreen.entryTooltip`)은 골든을 지키기 위한 임시 진입점이다. A-6b 탭·마이페이지 재설계에서 정식 진입으로 흡수.
