- 영속 `Room`, `QuestionThread`, post, mentor/profile 객체를 caller가 넘기는

### 최종 라우팅 방어 보강

통합 코드 리뷰에서 발견한 직접 URL 경계도 별도 커밋과 회귀 테스트로 고정했다.

- 같은 route pattern에서 ID만 A → B로 바뀌어도 모든 parameterized loader가 새 ID를
  다시 조회한다. 같은 URI rebuild는 중복 조회하지 않는다. 자체 상태를 갖는 IQ
  상세도 question ID key로 격리해 이전 질문의 입력·비동기 상태를 재사용하지 않는다.
- guest는 커뮤니티·멘토 읽기 표면만 사용할 수 있고 작성·수정 URL은 guest
  canonical인 `/mentors`로 수렴한다. 학생의 숏폼 작성 URL은 커뮤니티로 수렴하며
  mentor만 작성할 수 있다.
- 게시글 수정 URL은 post를 다시 읽어 현재 사용자와 `authorId`를 비교한다. 같은 URL
  상태에서 계정이 바뀌어도 사용자별 key로 권한을 다시 검증한다.
- production router의 durable leaf 18개를 `AppRouteCompletionBoundary`로 감쌌다.
  앱이 해당 URL에서 cold start한 경우에도 back/완료 동작은 소유 canonical URL로
  수렴하고, 기존 화면에서 push한 경우에는 원래 pop/result 계약을 그대로 유지한다.
- root 상세가 StatefulShellRoute의 탭 위를 덮는 동안에는 뒤의 활성 탭도 hidden으로
  판정한다. 앱 복귀 재조회는 즉시 fan-out하지 않고 상세를 pop한 뒤 정확히 1회
  처리한다.

새 회귀 테스트는 `parameterized_route_reload_test.dart` 3건,
`community_route_guard_test.dart` 6건,
`board_edit_route_authorization_test.dart` 4건,
`cold_route_completion_test.dart` 8건,
`shell_route_visibility_test.dart` 1건이다.
