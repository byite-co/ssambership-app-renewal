## 3. 네비게이션 구조

### 3-1. 하단 탭 — 학생·멘토 **동일한 한 벌**

`lib/app/home_shell.dart` + `lib/shared/constants/app_constants.dart` + `lib/app/app_tabs.dart`

| index | 라벨 | 아이콘 (Material Symbols rounded) | 배지 |
|---|---|---|---|
| 0 | 질문방 | `Icons.forum_rounded` | 없음 |
| 1 | 커뮤니티 | `Icons.groups_rounded` | 없음 |
| 2 | 멘토 찾기 | `Icons.search_rounded` | 없음 |
| 3 | 알림 | `Icons.notifications_rounded` | **있음** |
| 4 | 개별질문 | `Icons.question_answer_rounded` | 없음 |

- **탭바는 한 벌이다.** 학생·멘토가 라벨·순서·아이콘을 그대로 공유하고, 역할 분기는 **각 탭 화면 내부**에서 일어난다(`QuestionRoomScreen`·`IndividualQuestionTabScreen`이 `AuthService.instance.currentRole`로 분기).
- **알림 배지:** `_NotificationsTabIcon` → `NotificationBadgeController.instance.count`(서버 RPC `notification_unread_count_self`가 유일 소스). `null`(미확인)·`0` → 숨김, `100` 이상 → `99+`. 로컬 목록으로 개수를 계산하지 않는다.
- **게스트 제한:** `EntryGuard.guestAllowedTabs = {1, 2}` (커뮤니티·멘토찾기). 그 외 탭·마이페이지 탭 시 `/login?notice=login_required`로 이동. 게스트 시작 탭 = 2.
- **lazy 마운트:** `_built[]` 플래그로 **방문한 탭만** 빌드하고, 한 번 방문하면 `IndexedStack`으로 계속 살아 있다(상태·스크롤 유지). 활성 여부는 `ScreenVisibility`(InheritedWidget)로 하위에 전달.
- **탭 재선택 = 재조회 신호:** 탭0 → `DataRefreshBus.bumpQuestionRooms()`, 탭3 → `bumpNotifications()`.
- **탭 전환 채널:** `TabNavigator.request`(전역 `ValueNotifier<int>`). `AppTab.myPage = 100`은 가상 목적지로, 탭 전환 대신 마이페이지 push.

### 3-2. 마이페이지 진입

하단 탭이 **아니다.** `HomeShell` AppBar `actions` → `_ProfileCircleButton`(36×36 원형, `scheme.primary` 12% 배경 + `Icons.person_rounded`) → `Navigator.push(_MyPagePage)`.
마이페이지 안의 탭 이동 액션(알림·받은 질문 보기·질문하러 가기)은 **route를 pop 하면서 목적지 탭 index를 반환**하고, `HomeShell`이 받아 실제 탭을 전환한다.

## 6. 특별 확인 항목 답변

### 6-1. 연결노트 데이터 구조 ★ — **단일 편집이다(작성자당 1행). 누적 아님.**

| 질문 | 코드가 말하는 답 |
|---|---|
| 여러 건 생성 vs 한 건 수정 | **한 건 수정.** `upsertMyNote()`가 `(room, 내 author_id)` 행을 찾아 **있으면 UPDATE, 없으면 INSERT** — `question_room_write_repository.dart:185~248` |
| 저장 시 INSERT/UPDATE | 최초 1회만 INSERT, 이후 전부 UPDATE(`body` + `updated_at`) |
| 조회 건수 | `notes(roomId)`가 방의 **전 행**을 `updated_at desc`로 가져온다(`limit` 없음). 다만 실제로는 방당 학생1행·멘토1행뿐 |
| `author_role` 사용법 | **행 단위 분리 키.** 화면은 `author_id == 내 uid`로 '내 노트'(에디터에 시드)와 '상대 노트'(읽기 카드)를 나눈다. `author_role`(`student`/`mentor`)은 배지 라벨용. 저장 시 현재 role로 채우고, 학생·멘토 외 역할은 명시적 에러 |
| 앱의 손글씨(`ink_path`) 지원 | **없다.** `ConnectionNote`에 `inkPath`·`inkThumbPath`·`hasInk`가 남아 있으나 **UI 참조 0**. `connection_notes_screen.dart:21` 주석: "필기(잉크)는 연결노트에서 제거됨". 필기는 첨부 이미지 위 첨삭(`ScanAnnotationScreen`)으로만 존재 |

**추가 사실(개편 규모 판단에 직결):**

1. **DB는 누적을 막지 않는다.** `connection_notes`에 `(room, author)` UNIQUE 제약이 **없다** — 앱 주석이 실측으로 확인하고 있다(`write_repository.dart:189~192`: "DB에 (room, author) UNIQUE가 없어 과거 레이스로 내 노트가 2건 이상 존재할 수 있다"). 실제로 앱은 중복 행을 발견하면 최신 1건만 갱신하고 **나머지를 best-effort DELETE**한다. 즉 **"1행 강제"는 스키마가 아니라 클라이언트 쓰기 경로의 정책**이다.
2. **웹도 동일 정책이다.** `ssambership_web/components/qna/ConnectionNotesPanel.tsx:150` — "내 노트가 이미 있으면 추가 버튼을 숨겨 중복 생성 진입 자체를 없앤다(수정·삭제로만 관리)". 지시서에서 언급한 `학생의 노트` / `멘토의 노트` 제목과 **수정·삭제 버튼은 웹 UI**다(같은 파일 `:281`,`:293`,`:116`,`:126`). 앱 화면에는 **삭제 버튼이 없고**, 노트 번호 표기도 없다.
3. **따라서 "누적"으로 바꾸려면** DB 마이그레이션은 필요 없고, ① 앱 `upsertMyNote`의 UPDATE 분기 + 중복 삭제 로직, ② 앱 `ConnectionNotesScreen`의 "내 노트 = 단일 에디터" 구조, ③ 웹의 동일 정책(추가 버튼 숨김) — **세 곳을 함께** 바꿔야 한다. 앱만 고치면 웹이 중복 행을 정리하거나 숨긴다.

### 6-2. 앱에 없는 화면

**골든 캡처 시 걸림돌 (실측):**

1. **전역 싱글턴 3개** — `AuthService.instance`(role·게스트·차단 판정), `NotificationBadgeController.instance`, `DeletionNoticeController`. 주입 포트가 아니라 정적 인스턴스라 **역할별 캡처(학생/멘토)를 하려면 세션 상태를 만들어야 한다.** `AuthService.computeAccess`는 `@visibleForTesting` 순수 함수로 분리돼 있지만, 화면이 읽는 것은 인스턴스 상태다.
2. **Supabase 초기화** — 레포 기본값이 `const XxxRepository()`라 override를 주지 않으면 `SupabaseInit.clientOrNull`을 건드린다. 캡처 대상 화면마다 override 주입이 필수.
3. **테마 미적용** — 기존 위젯 테스트는 대부분 `MaterialApp(theme: ThemeData(splashFactory: NoSplash...))`처럼 **기본 테마**로 감싼다. 골든을 찍으려면 `AppTheme.build(AppRole.student|mentor)`로 감싸야 실제 화면과 같아진다.
4. **폰트** — 테스트 기본은 Ahem/기본 폰트라 Pretendard가 적용되지 않는다. 실제 화면과 같은 글자를 찍으려면 `loadFontFromList`류의 폰트 로딩이 필요하다(현재 그런 헬퍼 없음).
5. **셰이더** — HANDOFF.md가 기록한 헤드리스 컨테이너의 `ink_sparkle.frag` 이슈 이력이 있다(현재는 해소). 골든에서 InkWell 리플이 잡히지 않도록 `NoSplash` 고정 필요.

→ **결론:** 계정 없이 화면 캡처는 **가능하지만**, ①역할 싱글턴 세팅 ②레포 override ③`AppTheme` 래퍼 ④폰트 로딩 — 이 4가지를 담은 공용 테스트 하니스가 **아직 없다**(만드는 것은 이번 범위 밖).
